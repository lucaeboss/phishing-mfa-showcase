MFA phishing-resistance lab

A closed-loop demonstration of the modern credential-phishing chain and the defense that breaks it. Follow the stages in order — each one sets up the next.

Stage 0 · Set up the target

Create an ExampleCorp account protected by a password and TOTP two-factor auth. (A demo account is already seeded — see the server console.)

Enroll an account Normal login →

Stage 1 · Credential capture (the “evil portal”)

A fake ExampleCorp login page harvests the username and password in plaintext — the captive-portal attack from the project's hardware phase (T-Embed CC1101). Submit the seeded creds and watch them land in the capture log.

Open the evil portal QR delivery (quishing) →

Stage 2 · TOTP stops basic phishing

Take the captured password to the real login. You’ll hit the TOTP wall: a stolen password alone is not enough. This is the honest result — and exactly why attackers escalated.

Try the captured creds →

Stage 3 · Session theft bypasses 2FA

Log in fully (password + TOTP), then copy your demo_session cookie and hand it to replay_demo.py. The script reaches protected data without any second factor — the session token is the real prize. See the README for the exact steps.

Go to dashboard →

Stage 4 · The defense: passkeys (FIDO2)

Register a passkey and sign in with it. The credential is cryptographically bound to this origin, so the evil portal has nothing to harvest and an AiTM relay can’t obtain a usable assertion. This is your showstopper.

Open the passkey demo
