Credential phishing & multi-factor authentication

Modern phishing doesn't break the password. It steals the session.

A study of the credential-phishing chain — from rogue access points to real-time adversary-in-the-middle session theft — and the one form of authentication that finally breaks it.

AuthorLuca Caramihai AdvisorDr. Stephanos Mavromoustakos FieldCybersecurity StatusIn progress
01

A second factor was supposed to end password theft.

For a decade, two-factor authentication was the answer to phishing: steal a password and it is useless without the code. That remains true for simple, credential-only attacks — which is exactly why attackers stopped collecting passwords and started collecting something else. The modern target is the session token a service issues after a successful login. A second factor guards the login event; it does nothing for the session that follows. Whoever holds that token is treated as the user.

Evil-twin access points

A rogue Wi-Fi hotspot and a captive-portal login page record whatever a victim types. This project's hardware phase demonstrated the technique with a T-Embed CC1101 device running Bruce firmware.

Adversary-in-the-middle

A reverse-proxy phishing page relays the real login in real time, so even app-based and push approvals are completed by the victim and captured in transit.

Session theft

The post-login cookie is a bearer credential. Replaying it grants full access with no second factor re-checked — the pivot this project makes concrete.

02

Five stages, each paired with its defense.

The chain builds from a stolen password to a stolen session, then to the control that breaks it at the root.

01

Credential capture Attack

A fake login page — delivered by a rogue access point or a lookalike link — records the username and password in plaintext. The human trusts the page, not the origin.

Defense: user awareness, and password managers that refuse to autofill on the wrong origin — a machine check people lack.

02

The second factor holds Partial win

With TOTP, SMS, or push enabled, a stolen password alone fails at the code prompt. This genuinely stops basic, credential-only phishing — and pushes attackers to escalate.

Insight: the target moves from the password to whatever exists after login.

03

Adversary-in-the-middle & session theft Attack

A proxy relays the real login as it happens; the victim completes the second factor on the proxy, and the issued session token is captured. Replayed, it grants full access with nothing re-checked. The project demonstrates this against a controlled target only.

Partial defenses: short session lifetimes, token binding, step-up re-authentication, and conditional access reduce a stolen token's value.

04

Phishing-resistant authentication Defense

WebAuthn (FIDO2 / passkeys) replaces the shared secret with a key pair. The browser signs a challenge bound to the origin it is actually talking to, so a fake page or a relay on another origin cannot produce a signature the real service will accept.

Result: nothing to phish at Stage 01, nothing to relay at Stage 03, and only public keys stored on the server.

05

Harden the session Defense

Passkeys fix authentication; the session that follows is still a bearer token unless it is bound to the device and kept short-lived, with re-authentication required for sensitive actions.

Closing the door the attacker knocks on, and the window they climb through instead.

03

Why passkeys are categorically different.

Every method short of a passkey produces a secret the user can be induced to hand over — directly, or by completing it on a proxy. A passkey produces a signature cryptographically tied to the origin. There is nothing bearer-shaped to steal at the moment of authentication.

Nothing to phish

No password or code is ever typed into a page, so a fake portal has nothing to record.

Origin-bound

The authenticator signs data that includes the real origin; a relay on another origin cannot forward a usable assertion.

No server secret

The service stores only public keys, so a breach does not yield reusable credentials.

06

Contained by design.

This project never clones, proxies, or contacts a real website or identity provider. The target is a fictional service built for the lab and run on an isolated host.

Session theft is demonstrated by replaying a token against the lab's own application — not with a reusable tool against live services. Radio testing is confined to owned devices in a controlled space, using synthetic credentials that are deleted after the final demonstration.

Authorized use only. The techniques here are presented for education and defense. Operating a rogue access point against other people's devices, intercepting their traffic, or cloning a real login to collect real credentials can be unlawful even without intent to harm.
